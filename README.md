GitHub Webhook Event Tracker

Project Overview

    This project implements a GitHub Webhook Event Tracker as part of the TechStaX SDE-1 assignment.
    The system listens to GitHub webhook events such as Push, Pull Request, and Merge, stores them in MongoDB, and displays them in real time on a web dashboard.

    The main goal of the project is to demonstrate backend webhook handling, event processing, data persistence, and a dynamic frontend interface in a structured and scalable way.

Features

Captures GitHub webhook events:

    Push

    Pull Request

    Merge

Parses webhook payloads and extracts relevant information

Stores events in MongoDB with proper schema and timestamps

Prevents duplicate event storage using unique identifiers

Sorts events chronologically with priority-based ordering

Converts timestamps to IST timezone for consistent display

Real-time UI updates using polling (every 15 seconds)

Clean and readable UI with event type indicators

Safe handling of missing or inconsistent data fields

Modular backend and frontend structure

System Architecture

The system follows an event-driven architecture.

    A GitHub action occurs (Push, Pull Request, Merge).

    GitHub sends a webhook payload to the Flask backend.

    The backend parses the payload and extracts event details.

    The event is stored in MongoDB with timestamp and metadata.

    The frontend periodically requests the latest events from the backend.

    The events are rendered on the dashboard in a structured timeline.

Flow:

    GitHub → Webhook → Flask API → MongoDB → Frontend Dashboard

Data Model

Each event stored in MongoDB follows this structure:

{
    "request_id": "unique_event_id",
    "author": "github_username",
    "action": "PUSH / PULL_REQUEST / MERGE",
    "from_branch": "source_branch",
    "to_branch": "target_branch",
    "timestamp": "event_time",
    "created_at": "db_insert_time"
}

Event Ordering Logic

GitHub often triggers multiple events within the same second during merge operations.
To ensure logical and consistent ordering, the system implements:

Timestamp-based sorting

Priority-based ordering:

    PULL_REQUEST

    MERGE

    PUSH

Safe timestamp parsing with fallback handling

Secondary sorting using database insertion time

This ensures that events are displayed in a meaningful chronological order similar to real GitHub activity timelines.

Setup Instructions

Step 1: Clone the Repository

    Two repositories are used as required by the assignment:

    action-repo (dummy repository for triggering GitHub events)

    webhook-repo (main project repository)

    git clone <webhook-repo-url>
    cd webhook-repo

Step 2: Create Virtual Environment
    python -m venv venv
    venv\Scripts\activate

Step 3: Install Dependencies
    pip install -r requirements.txt

Step 4: Configure Environment Variables

    Create a .env file in the project root:

    MONGO_URI=mongodb+srv://<username>:<password>@cluster.mongodb.net/github_webhooks

Step 5: Run the Flask Server
    python app.py


Server runs at:

    http://127.0.0.1:5000

Step 6: Expose Local Server Using Ngrok
    ngrok http 5000


Copy the public URL generated by ngrok.

Step 7: Configure GitHub Webhook

In the action-repo:

    Go to Settings → Webhooks → Add Webhook

    Payload URL: <ngrok-url>/webhook

    Content type: application/json

Select events:

    Push

    Pull Request

    Merge

Key Design Decisions

    MongoDB was chosen for flexible schema and scalability.

    Priority-based sorting was implemented to handle simultaneous GitHub events.

    Polling was used instead of WebSockets to keep the system simple and reliable.

    Defensive programming was applied to handle inconsistent webhook payloads.

    The UI was designed to be minimal, readable, and responsive.

Future Improvements
